Round Ledgers

This repository uses two round counters:

  • Repository round (repo_round): one row in the root log.md, assigned to every merged repository change. It records project-level history: workflow changes, tooling, framework documents, bundle updates, and snapshot-publication work.
  • Bundle round (bundle_round): one row in a bundle-local log.md and one inquiry/round-NNNN.md file, assigned only when that bundle's statement trajectory changes. A repository change can affect zero bundles, one bundle, or several bundles.

The counters are intentionally independent. If a repository change updates framework-self, root log.md may advance from repo round 8 to 9 while bundles/framework-self/ advances from bundle round 7 to 8. That is not an inconsistency; it means one repository-level change produced one bundle-local move.

Snapshot Rule

Snapshots in ../okf-bundle-snapshots are named by bundle round:

<YYYY-MM-DD>-r<bundle_round>-<source-shorthash>

The snapshot manifest and catalog also record source_repo_round, so the viewer can show which repository round produced the snapshot. Do not rename a bundle snapshot to the repository round unless the bundle's own inquiry round has the same number.

When a repository change updates one or more bundles, publish each affected bundle after the source commit reaches main:

okf-fc publish bundles/<bundle-id> --dest ../okf-bundle-snapshots

The publish command writes a self-contained snapshot, deterministic zip, manifest, structure visualization, catalog rows, and viewer indexes. Commit those generated artifacts in ../okf-bundle-snapshots.

If a repository change does not update any bundle, do not create a bundle snapshot. Its root log.md row is sufficient.
