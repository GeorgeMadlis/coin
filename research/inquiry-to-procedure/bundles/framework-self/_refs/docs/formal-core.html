Formal Core

This document fills the Step 2 deliverable for the statement-evolution framework. It formalizes the static observer-disagreement cross-section and the dynamic round model described in docs/framework_v3.md, using the vocabulary fixed in docs/glossary.md and the literature boundaries recorded in docs/related-work.md.

Status note: the definitions below are part of the framework. The propositions are not all theorems. Each proposition states its assumptions, epistemic status, supporting argument, boundary cases, and revision conditions.

1. Notation And Domains

Let T = {0, 1, 2, ...} be the round index set. Let P be the set of parties or agents participating in a statement trajectory. Let Y be an interpretation space: labels, verdicts, claims, model outputs, narratives, or structured statements. When two observers use different output vocabularies, assume an explicit comparison relation ~ on outputs. If no comparison relation is available, equality of raw strings is not enough to diagnose substantive agreement.

The framework distinguishes three uses of "record":

  • E: the event stream, including the historical events under discussion and later inquiry events such as claims, objections, evidence submissions, and revisions.
  • R = r(E): the surviving record available to present observers after a lossy recording function r.
  • R as a bundle axis value, written fc-axis: R, meaning Results. This is a metadata label, not the formal surviving-record symbol.

The static chain is:

E -> r -> R -> O_i -> y_i

where observer O_i = (C_i, f_i) emits output y_i = f_i(R cap C_i).

The dynamic chain is the same model indexed by rounds, with the additional fact that the trajectory's own rounds become new events:

E(t+1) = E(t) concat q(t)

where q(t) is the recorded-or-unrecorded event generated by round t.

2. Static Model

2.1 Event Stream

An event stream E is an ordered sequence, partially ordered history, or other event structure representing what occurred before present interpretation. The framework does not require observers to access E directly. In historical, scientific, institutional, or repository settings, present observers normally access only traces left by prior recording processes.

Repository-specific observation: in this repository, the event stream includes commits, pull requests, bundle rounds, documentation edits, and derived-artifact generation. The committed HEAD of main is the canonical current source state, but it is still a record of past events, not the events themselves.

2.2 Recording Function

The recording function r maps the event stream into a surviving record:

r: E -> R.

r may stand for witnesses, instruments, archives, publication pipelines, version-control commits, bundle manifests, data-cleaning procedures, or any other process that selects and encodes some aspects of E. It is generally lossy and non-invertible. The full specification of r may itself be absent from R.

Two levels of loss matter:

  • Loss in the recorded content: some fact about E is not retained in R.
  • Loss in the recorder specification: facts about how r selected, transformed, omitted, timestamped, or normalized events are not retained.

The first can make an object-level claim underdetermined. The second can make the extent of underdetermination itself inaccessible.

2.3 Surviving Record

The surviving record is:

R = r(E).

Present observers compute over R, not over E. R may be a set, sequence, or structured collection of records. The notation R cap C_i denotes the part of the surviving record available to, attended to by, or selected by observer i. If C_i is already defined as a subset of R, then R cap C_i = C_i; the expanded notation is retained to emphasize that present observation is mediated by R.

2.4 Observer

An observer is:

O_i = (C_i, f_i).

C_i is the context window: the accessible or attended subset of the surviving record. f_i is the compression function or frame: a bounded map from accessible records to an interpretation output. A compression function induces an equivalence relation on record states: two record states are equivalent for observer i when f_i maps them to the same output.

The framework treats f_i computationally. It may encode a model, prior, classification scheme, narrative frame, legal rule, threshold, method, or translation procedure. It is not assumed to be neutral or complete.

2.5 Observer Interpretation

Observer i emits:

y_i = f_i(R cap C_i).

An interpretation can be a verdict, belief state, claim, explanation, or structured answer. It is always relative to R, C_i, and f_i. The framework therefore never equates "what the observer says" with "what happened in E" unless separate assumptions justify that equation.

2.6 Disagreement

Observers i and j disagree when their comparable outputs are not equivalent:

D(i, j; R) iff not (y_i ~ y_j).

If both outputs live in a common interpretation space and exact equality is the chosen comparison relation, this reduces to:

f_i(R cap C_i) != f_j(R cap C_j).

Disagreement is a relation over observer outputs. Diagnosing the cause of disagreement requires additional counterfactual tests over contexts, frames, and the retained record.

2.7 Type I, Type II, And Type III Conditions

The Type I/II/III taxonomy applies only when a live counter-position exists; that is, only to contestation-stage rounds in the dynamic model. A static cross-section can still state the corresponding conditions.

Let Q be the disputed question or proposition. Let A(R) be the accessible record closure: the records currently present in R that could in principle be shared or inspected under the available resource limits.

Type I: different context windows.

A disagreement has a Type I component when the outputs differ because observers use different accessible subsets of R:

  • C_i != C_j over accessible records;
  • there is record content d in A(R) available to at least one observer and absent from the other's context;
  • holding the relevant frame fixed or mutually translated, adding d can remove the disagreement.

Type I is data-resolvable in principle when the missing records are present in R, shareable, and computable by the receiving observer. It may remain blocked in practice when decompression, verification, or integration of another observer's evidence is too costly for bounded observers.

Type II: different compression functions.

A disagreement has a Type II component when the accessible record is shared, or would be shared after Type I closure, but outputs still differ because frames diverge:

  • R cap C_i and R cap C_j are evidence-equivalent for the disputed question;
  • f_i and f_j induce different partitions, thresholds, priors, methods, or category schemes over that evidence;
  • adding more of the same accessible record does not by itself remove the disagreement;
  • a translation between frames or an adopted third frame could remove or conventionalize the disagreement.

Type II is frame-resolvable in principle, not data-resolvable by mere context enlargement.

Type III: disputed content outside the surviving record.

A disagreement has a Type III component when the surviving record is insufficient to determine the disputed proposition. A precise condition is:

there exist event streams E_a and E_b such that r(E_a) = r(E_b) = R, but Q is true in E_a and false in E_b.

Then no present observer whose input is only R can determine Q by more computation, a larger context window, or a different frame. The result can be conventionalized by adopting an inference procedure over traces, or declared underdetermined, but the absent fact is not recovered from R.

2.8 Resource-Inaccessible Vs. Irrecoverable Information

The framework keeps two limits separate.

Currently inaccessible because of resource limits:

  • records present in R but not yet found, parsed, afforded, licensed, downloaded, translated, or read;
  • computations over retained records that are too expensive to rerun now;
  • comparisons between frames whose translation cost exceeds available time, compute, expertise, or attention;
  • latent implications of R that require running a long inquiry process to expose.

These are computational limits. They may change as resources, tools, or coordination improve.

Irrecoverable because not retained in R:

  • events or attributes omitted by r;
  • discarded raw measurements after only aggregates survive, unless the aggregate is sufficient for the disputed question;
  • unrecorded code versions, dataset versions, prompts, thresholds, reviewer decisions, witness observations, or chain-of-custody facts needed to decide Q;
  • the specification of r itself when no record identifies how selection, transformation, or omission occurred;
  • unrecorded rounds of a statement trajectory.

These are informational limits. More compute over the same R cannot recover the missing fact.

3. Dynamic Model

3.1 Observer Trajectory

An observer trajectory indexes observer state by round:

O(t) = (C(t), f(t)).

C(t) is the context window at round t. f(t) is the frame or compression function at round t. The observer output at the start of round t is:

claim(t) = f(t)(R(t) cap C(t)).

For a multi-party trajectory, O(t) denotes the trajectory's shared effective state at round t. Party-local histories are restrictions of the shared round sequence, defined below.

3.2 Claim State

A claim state packages the parts of the trajectory relevant for a round:

S(t) = (E(t), R(t), C(t), f(t), claim(t), L(t), status(t)).

L(t) is the set of live positions or commitments known in the record at the start of round t. status(t) is the current status: open, resolved, or underdetermined. Other implementations may add metadata, but the formal model requires at least the event stream, surviving record, context, frame, emitted claim, live-position set, and status.

3.3 Move

A move is the action made in a round. Let:

m(t) in M = {question, objection, evidence, frame-change, convention, verdict-revision}.

This set names operational move types, corresponding to fc-move. The move type does not uniquely determine the stage. For example, an objection can be critique or contestation, and evidence can be formation, enrichment, or contestation.

3.4 Evidence Update

Let e(t) be record content introduced or selected during round t. Under the normal bundle discipline:

C(t+1) = C(t) union e(t).

Strictly, e(t) must be content in or added to R(t+1). In external-world inquiries, new evidence may be newly discovered records, newly generated measurements, or links to previously uninspected material. In repository inquiries, it may be a committed document, round record, code change, render, or manifest.

Evidence deletion breaks monotonicity. If evidence is removed from R, then the simple union update no longer describes the actual record. The bundle rule therefore treats deletions as dangerous: a deleted or unpinned source can create future Type III uncertainty about the trajectory's own history.

3.5 Frame Update

A frame update is:

f(t+1) = U_f(f(t), m(t), e(t), S(t)).

U_f may leave the frame unchanged, translate between frames, adopt a joint convention, revise a verdict rule, or replace a prior compression function. The formal core does not assume monotonic belief revision: later evidence or frame changes may retract earlier beliefs, re-open consolidated points, or expose that an earlier stage classification was provisional.

3.6 Round Transition Operator

The round transition operator is:

Tau_t(S(t), m(t), e(t)) = S(t+1).

At minimum it satisfies:

  • E(t+1) = E(t) concat q(t), where q(t) is the event generated by the round;
  • R(t+1) = r(E(t+1)), or under explicit bundle discipline, R(t+1) = R(t) union record(q(t)) union e(t) when the round is retained;
  • C(t+1) = C(t) union e(t) for retained evidence additions;
  • f(t+1) = U_f(f(t), m(t), e(t), S(t));
  • claim(t+1) = f(t+1)(R(t+1) cap C(t+1));
  • L(t+1) updates live positions according to the move and any revised claim;
  • status(t+1) updates if the round resolves, consolidates, or declares underdetermination.

The recursion is important: every round appends to the event stream and passes through a recording function. The bundle's inquiry axis is the explicit recording function for the trajectory itself.

3.7 Statement Trajectory

A statement trajectory is the recorded sequence:

Sigma = (S(0), m(0), S(1), m(1), S(2), ...).

It may be finite or open-ended. It can pass through formation, enrichment, critique, contestation, and consolidation, and it can revisit stages after later supersession. A trajectory with no contestation rounds is still a valid statement trajectory.

3.8 Stage Function And Stage Trajectory

The stage function maps rounds to lifecycle stages:

stage: T -> {formation, enrichment, critique, contestation, consolidation}.

The stage trajectory is:

Stage(Sigma) = (stage(0), stage(1), stage(2), ...).

Stage is determined by the round's role in the statement lifecycle, not by move name alone:

  • formation: the first round that emits the statement on this trajectory;
  • enrichment: information is added with no standing counter-position;
  • critique: a frame, assumption, or claim is probed without a maintained rival position;
  • contestation: a live counter-position stands against the current claim;
  • consolidation: a convention, verdict revision, settlement, supersession, or underdetermined closure is adopted.

3.9 Relationship Between fc-move And fc-stage

Let mu(t) be the recorded fc-move and stage(t) the recorded fc-stage. There is an admissibility relation A subset M x Stages:

  • (evidence, formation), (evidence, enrichment), (evidence, contestation);
  • (question, enrichment), (question, critique);
  • (objection, critique), (objection, contestation);
  • (frame-change, contestation), (frame-change, consolidation);
  • (convention, consolidation);
  • (verdict-revision, consolidation).

stage(t) is not a function of mu(t) alone. It is a function of the prior state, the move, the resulting state, and the recorded rationale:

stage(t) = sigma(S(t), mu(t), e(t), S(t+1), rationale(t)).

This matters in adversarial or ambiguous cases. A party may present an evidence move as neutral enrichment while actually maintaining a rival position; that should be classified as contestation if the record supports the presence of a live counter-position. Conversely, an objection used only to probe an assumption is critique, not contestation. If the record does not show whether a rival position exists, the stage classification should be marked PROVISIONAL or UNVERIFIED rather than forced.

3.10 Type Trajectory

Define a contestation-type function only on contestation rounds:

type(t) in {I, II, III, resolved} if stage(t) = contestation.

It is undefined otherwise. The type trajectory is the contestation restriction of the stage trajectory:

Type(Sigma) = ((t, type(t)) : t in T and stage(t) = contestation).

Formation, enrichment, critique, and consolidation rounds do not carry fc-type-at-round. This avoids conflating lifecycle role with disagreement diagnosis.

3.11 Sequential Multi-Observer Party Assignment

The operational multi-observer model is one shared round sequence with a party assignment:

p: N -> P.

Round t is authored by party p(t). Each party acts on the full accumulated state left by all earlier rounds. Party a's contribution history is the restriction:

Sigma|a = (t, S(t), m(t), S(t+1) : p(t) = a).

This is not an independently-clocked private branch. A parallel-branch model with separate O_a(t) and O_b(t) trajectories later fused is representable in general, but it is not the repository workflow. The repository adopts the sequential realization because the canonical-state rule makes one committed mainline authoritative, and because disagreement between agents is recorded as content in the inquiry axis rather than as competing branch topology.

3.12 The Diagonal Single-Observer Case

The single-party case sets P = {self} and p(t) = self for every round. The same observer can disagree with its earlier time slice:

D(t+1, t) iff not (claim(t+1) ~ claim(t)).

If the disagreement occurs during contestation, the same Type I/II/III taxonomy applies:

  • new retained data against one's past self: Type I component;
  • a changed frame against one's past self: Type II component;
  • recognition that the needed past fact was never retained: Type III component.

The diagonal is broader than contestation. A single party can enrich, critique, or consolidate its own earlier statement without opening a live disagreement.

3.13 Supersession

Supersession is an append-only revision relation. A concept version established at round k may be replaced at round t > k by a new version that records:

  • fc-round: t;
  • fc-supersedes: path@rk;
  • a round file explaining the move, evidence, state effect, and rationale.

The prior text remains recoverable from Git history. Supersession is not deletion, and it is not retroactive renumbering.

3.14 Consolidation And Later Supersession

Consolidation sets a current status, convention, verdict, or settlement. It is not an absorbing terminal state. A later round may add evidence, critique the settlement, contest it, or supersede the consolidated concept. Therefore there is no stage-level floor analogous to the Type III residue. Consolidation is a current-state marker under append-only provenance, not an eternal guarantee.

3.15 Bottoming-Out And Underdetermined Closure

A contestation stretch bottoms out when the remaining disagreement is invariant under admissible evidence and frame moves. Formally, for residual disputed proposition Q at round t, bottoming-out is supported when:

  • no available evidence update e drawn from R changes the residual disagreement;
  • no admissible frame update under the parties' accepted frame set resolves the residual;
  • there exist record-compatible event streams that disagree on Q, or the missingness of r is sufficient to make that possibility unavoidable.

If these conditions hold because Q is absent from R, the correct closure is fc-status: underdetermined. If the search over evidence or frames is incomplete because of current resources, the closure should be marked PROVISIONAL or NOT MEASURABLE rather than final.

4. Propositions And Assumptions

The labels P1-P5 and P4' reconstruct the current v3 framework. The status terms below are intentionally cautious:

  • definition: true by stipulation inside the framework;
  • derivable proposition: follows from definitions and stated assumptions;
  • theorem candidate: plausibly formalizable as a theorem after stronger technical assumptions are fixed;
  • conjecture: plausible but not proven;
  • empirical regularity: expected pattern to be tested in later steps.

P1. Type II Frame Translation Is Practically Blocked

Precise statement. In a Type II contestation, where observers share the relevant accessible record but use different compression functions, convergence by frame translation is blocked in practice when computing an adequate translation between f_i and f_j, or evaluating a jointly acceptable third frame, exceeds the observers' resource bounds.

Assumptions.

  • Present observers are computationally bounded.
  • The disagreement remains after Type I context closure.
  • f_i and f_j induce materially different partitions, thresholds, priors, or category schemes.
  • No already-accepted common frame or lookup table resolves the outputs.
  • "Convergence" means substantive output equivalence under the comparison relation ~, not merely verbal compromise.

Epistemic status. Theorem candidate under explicit complexity assumptions; otherwise a proposed extension and empirical regularity. It is not established as a theorem for human or AI inquiry in this repository.

Supporting argument. If the disagreement is located in f rather than C, then adding records alone is insufficient. The task becomes translating, comparing, or replacing compression functions. For rich frames, that task can require reconstructing why each frame groups record states as it does. This is the computational-boundedness contribution inherited from bounded rationality and compression views of interpretation.

Counterexamples and boundary cases.

  • The frames are finite, explicit, and connected by a small translation table.
  • A domain standard already defines the joint frame.
  • The apparent Type II disagreement was actually Type I missing context.
  • The parties accept a convention without needing full frame translation.
  • An unbounded or much more capable observer can compute the translation.

Revision or falsification evidence. P1 would need revision if a general, resource-cheap translation method reliably produced convergence across rich frame disagreements, or if measured persistence of Type II disagreements did not correlate with frame distance or translation cost.

P2. Type III Is Invariant Under Context Enlargement And Frame Translation

Precise statement. If a disputed proposition Q is Type III with respect to surviving record R, meaning there exist E_a and E_b such that r(E_a) = r(E_b) = R but Q differs between them, then no context enlargement within R and no frame translation whose input is only R can determine Q.

Assumptions.

  • Present observers access only R and functions of R.
  • The Type III condition is correctly diagnosed.
  • No new independent record is added that changes R.
  • Q is not inferable from sufficient retained statistics in R.

Epistemic status. Derivable proposition, and theorem candidate in a fully specified information-theoretic model.

Proof sketch. Let g be any present-observer procedure: a context expansion, frame translation, inference rule, or model whose input is only R. Since r(E_a) = r(E_b) = R, g(R) is identical in both possible event streams. But Q has different truth values in E_a and E_b. Therefore g(R) cannot determine which event stream occurred. It can select a convention over compatible histories, but it cannot recover the absent fact.

Counterexamples and boundary cases.

  • The claim was mislabeled Type III; R actually contains a sufficient record.
  • r is non-invertible overall but invertible with respect to Q.
  • A new archive, witness record, checksum, or instrument log is added, changing the surviving record from R to R'.
  • The question is not about E but about which convention to adopt over R.

Revision or falsification evidence. A successful recovery of a correctly diagnosed Type III fact using only the original R would falsify P2. More likely, such a case would show that the original Type III diagnosis was wrong or that the record had silently expanded.

P3. Lost Recorder Specification Causes Type III To Be Misread As Type II

Precise statement. When the specification of r is itself absent from R, observers may be unable to tell whether a persistent disagreement is caused by different frames over a sufficient record or by information missing from the record. Under the additional assumption that observers treat the record as sufficient by default, Type III disputes are systematically misclassified from within as Type II frame disputes.

Assumptions.

  • The disputed fact depends on how r selected, transformed, or omitted events.
  • The relevant specification of r is absent from R.
  • Observers cannot independently audit missingness.
  • Observers have competing frames capable of filling the absent content.
  • The social or methodological setting encourages record-sufficiency assumptions.

Epistemic status. Conjecture and empirical regularity. It is not a theorem: the word "systematically" depends on observer behavior and domain practice.

Supporting argument. If the record does not reveal what it failed to retain, then an observer inside the record cannot distinguish "your frame compresses the retained facts differently" from "the facts needed to decide this were not retained." Each observer's frame supplies a completion of the gap, so the dispute appears to be about bias, priors, or categories.

Counterexamples and boundary cases.

  • The record includes explicit missingness metadata or provenance warnings.
  • Domain practice assumes incompleteness and marks underdetermination early.
  • Independent sources allow observers to bound what r omitted.
  • Strategic behavior or incentives, not hidden missingness, explain the disagreement.
  • Observers misclassify the dispute as Type I rather than Type II.

Revision or falsification evidence. P3 would need revision if case studies showed observers reliably detect Type III causes without recorder specification, or if persistent missing-record disputes were more often classified as Type I, bad faith, or convention disputes than as Type II.

P4. Truthful Recorded Contestation Descends And Bottoms Out

Precise statement. In a contestation stretch whose moves are truthful, recorded, fair, and sufficiently exhaustive over accessible evidence and a bounded or fairly scheduled frame set, Type I components resolve first by context sharing; remaining Type II components resolve, translate, or conventionalize; any residual disagreement bottoms out at Type III underdetermination. The termination criterion is invariance of the residual disagreement under admissible evidence updates and frame moves.

Assumptions.

  • The stretch is genuinely contestation-stage: a live counter-position exists.
  • Moves are truthful: parties do not knowingly suppress, fabricate, or distort evidence.
  • Rounds are recorded append-only, so prior moves remain inspectable.
  • Evidence updates are monotonic with respect to retained R; no relevant evidence deletion occurs.
  • Accessible Type I evidence is finite or fairly scheduled so it is eventually shared.
  • Frame candidates are bounded, or frame exploration is governed by a fairness rule preventing endless evasion.
  • The parties accept a termination rule for conventionalized Type II residues and underdetermined Type III residues.

Epistemic status. Derivable as a termination result only under strong finite or fairness assumptions. In the general framework it is an empirical regularity and theorem candidate, not an established theorem.

Supporting argument. Type I differences are located in accessible context, so truthful sharing should remove them before deeper causes are exposed. Once the accessible record is shared, any remaining divergence must be located in frames or in absent facts. Frame work can translate or conventionalize Type II components. If the residual is invariant under both evidence and accepted frame moves, and if compatible event streams still differ on the disputed proposition, the stretch has reached a Type III floor.

Counterexamples and boundary cases.

  • Frame oscillation: parties repeatedly change f after each evidence update.
  • Strategic moves: evidence flooding, selective disclosure, bad-faith objections, or deliberate ambiguity prevent descent.
  • Non-monotonic belief revision: later evidence legitimately reopens a Type I component that seemed closed.
  • Evidence deletion: a once-retained record disappears, creating a new Type III limit.
  • Unbounded frame invention: parties can always introduce a new frame, so Type II never reaches a stable conventionalization point.
  • New external evidence expands R, so a declared Type III floor was only provisional relative to the previous record.

Revision or falsification evidence. P4 would be weakened if well-recorded, truthful, non-adversarial contestation stretches with fair evidence and frame exploration frequently failed to show descent, or if Type II/III components regularly resolved before accessible Type I differences without an explanation in the domain structure.

P4'. Stage Ordering Across Whole Trajectories

Precise statement. P4' has two parts.

P4'(a): For a given statement trajectory, formation precedes every enrichment, critique, contestation, or consolidation round about that statement.

P4'(b): Across whole trajectories, stages may tend toward consolidation, but the claim is not monotone and not guaranteed. Consolidation can be superseded, so there is no stage-level floor analogous to Type III bottoming-out.

Assumptions.

  • A "given statement" has an identifiable first emitted claim.
  • Later rounds are about that statement or its recorded supersessions.
  • Stage classifications are assigned from the live state, not move name alone.
  • For the stronger P4'(b), one would need assumptions about cooperative inquiry, finite problem scope, stable records, and non-adversarial move selection.

Epistemic status. P4'(a) is definitional. P4'(b) is a conjecture and empirical hypothesis, not a theorem.

Proof sketch for P4'(a). A round cannot enrich, critique, contest, or consolidate a statement before that statement exists on the trajectory. Formation is defined as the first emission of the statement. Therefore formation precedes all later stages for that statement.

Supporting argument for P4'(b). Many inquiries aim to reduce open questions and eventually adopt a verdict, convention, or underdetermined closure. P4's descent may still hold inside any contestation stretch that the trajectory enters. It is also plausible that critique before first contestation reduces later contestation length and post-consolidation supersession, because some frame and context issues have already been exposed.

Counterexamples and boundary cases.

  • A consolidated point is later superseded by new evidence.
  • A trajectory cycles through enrichment and critique indefinitely.
  • A strategic party repeatedly reopens contestation after settlement.
  • A statement is abandoned open rather than consolidated.
  • Multiple statements are conflated, making "first formation" ambiguous.

Revision or falsification evidence. P4'(b) would be weakened if recorded trajectories showed no movement toward consolidation, or if critique before contestation did not correlate with shorter contestation stretches or lower post-consolidation supersession rates. This repository's single framework-self trajectory is an example source, not validation by itself.

P5. Dialogic Irreducibility

Precise statement. The outcome of a genuine statement trajectory cannot in general be predicted without running the rounds. Corollaries: no party can legitimately pre-announce where an open trajectory will converge; shortcutting rounds tends to misclassify disagreement type by treating Type II or Type III residue as if it were Type I.

Assumptions.

  • The trajectory permits nontrivial evidence discovery, frame revision, or party response.
  • Future moves are not fully known to the predictor.
  • The update operator can encode sufficiently rich computation or inquiry.
  • Observers are bounded.
  • "Outcome" includes final claim, stage path, type path, and closure status.

Epistemic status. Conjecture and theorem candidate under computational universality assumptions. It is not established as a theorem for this repository.

Supporting argument. If future evidence, objections, and frame changes can materially alter both state and classification, then predicting the final state requires predicting the path of those moves. For sufficiently rich trajectories, the path can embody an irreducible computation or an open-ended inquiry whose result is known only after the relevant rounds occur.

Counterexamples and boundary cases.

  • A finite deterministic workflow with known inputs and known update rules.
  • A trivial trajectory where no evidence or frame changes are possible.
  • A domain with a canonical procedure that already determines the verdict.
  • A predictor with access to all future moves, making the "future" no longer open.

Revision or falsification evidence. P5 would need revision if rich statement trajectories could generally be predicted accurately from initial state summaries without running their rounds, including their stage and type paths.

5. Framework-Self Worked Encodings

These examples use only recorded rounds from bundles/framework-self/inquiry/index.md⚠ unresolved. They illustrate how repository events can be encoded. They are not empirical validation of general propositions.

5.1 Round 1 As Formation

Bundle round 1 created the pilot self-description bundle. In the dynamic model:

  • q(1) is the repository event "pilot bundle initialized."
  • record(q(1)) includes bundles/framework-self/inquiry/round-0001.md and the initial concept files.
  • stage(1) = formation in the index summary, because the bundle's self-description statement first appears on the trajectory.
  • type(1) is undefined, because no live counter-position existed.

This is a formal encoding of a repository event, not evidence that all formations behave this way.

5.2 Round 3 As Contestation

Bundle round 3 records a second-observer validation. The inquiry index classifies it as contestation: mechanical Type I defects were resolved, exposing an unresolved Type II residue about labeling and specification gaps.

Encoding:

  • p(3) = claude.
  • mu(3) = objection.
  • stage(3) = contestation, because a live counter-position stood against the prior bundle state.
  • type(3) includes Type I components and a remaining Type II residue, as summarized by the current inquiry index.

This is illustrative evidence that the repository can record a contestation round. One contestation round is not enough to validate P4's descent claim.

5.3 Round 4 As Consolidation

Bundle round 4 adopted the v3 frame: statement evolution became the broader object, and observer disagreement became the contestation regime. It superseded current concept files that described the v2 scope as current.

Encoding:

  • mu(4) = frame-change.
  • stage(4) = consolidation, not contestation, because the new frame was adopted rather than maintained as a rival position.
  • Supersession links preserve the prior v2-current wording in Git history.

This shows why frame-change cannot uniquely determine stage. The same move name could have been contestation if a rival frame had remained live.

5.4 Round 10 As Enrichment

Bundle round 10 completed the Step 1 related-work positioning and superseded one foundation page to include dialogue-game sources. It is classified as enrichment because it added scholarly context without a live counter-position.

Encoding:

  • p(10) = codex.
  • mu(10) = evidence.
  • stage(10) = enrichment.
  • type(10) is undefined.

This is evidence for the repository's current self-description, not evidence that related-work enrichment generally causes convergence.

6. Boundaries And Labels

The framework's current formal status is deliberately mixed:

  • Static definitions and stage/type distinctions are definitions.
  • P2 follows from the Type III definition under explicit assumptions.
  • P1, P3, P4, P4'(b), and P5 remain open in varying degrees and should not be described downstream as established universal theorems.
  • Claims about frame oscillation, strategic moves, non-monotonic revision, evidence deletion, and supersedable consolidation are boundary conditions, not implementation details to hide.
  • Any bottoming-out claim must say whether it is final relative to a fixed R or only PROVISIONAL because the search over records or frames is incomplete.
