Agent Guide

Agent Guide

Supersedes the dual-agent fusion protocol; retired 2026-07-19, see git history.

This file is the single source of truth for any agent (Claude Code, Codex, or others) working in this repository.

One Change, One PR

Each change request — whether a Step 0–9 deliverable or a later contribution — is executed as exactly one PR, opened from a short-lived branch work/<slug> by whichever single agent is invoked. The PR is reviewed, merged to main, and the branch is deleted after merge. For the Step 0–9 deliverables, steps still run in order: do not start Step N+1 while Step N is unmerged, and one step is still exactly one PR.

Sequential Multi-Observer Rule

Work is single-agent and linear: one agent opens one PR against one work/<slug> branch at a time. Different agents may still participate in the project, but sequentially, never on parallel branches for the same step.

When the human wants a second opinion on work that has already merged, the second agent is invoked after the first PR merges. It works on its own work/<slug> branch and records any differing views — objection, critique, counter-evidence — as ordinary rounds/moves in the affected bundle's inquiry/ axis, and as its own line in log.md attributed to its own party. Each agent is treated as a distinct observer: a subject with its own opinions, questions, and understanding, whose contribution enters the record as content, not as a parallel branch. Disagreement between agents is thereby captured as inquiry content, not as branch topology.

Canonical-State Rule

The committed HEAD of main is the canonical current state of every bundle in bundles/. Anything derived from a bundle — rendered HTML, exported zips, catalogs — must be pinned to a specific commit, not to a branch or working tree state.

Round Ledger Discipline

Every merged PR appends one line to the root log.md using the documented format. This is the repository round (repo_round). party is the acting agent for that round: codex | claude | human | <other>. The ledger is append-only: never rewrite or delete past ledger lines, and never force-push main.

Bundles have their own bundle rounds (bundle_round) in bundles/<id>/log.md and bundles/<id>/inquiry/round-NNNN.md. A repository round can affect zero bundles, one bundle, or several bundles. When it affects a bundle, add the corresponding bundle-local round and publish that bundle to ../okf-bundle-snapshots after the source commit reaches main. Snapshot names use bundle rounds, while manifests/catalog rows record the source repository round separately. See docs/round-ledgers.md.

Reference, Don't Subsume

Bundles link to external code/data at pinned commits and checksummed dataset versions; nothing external is vendored into this repo.

Stub Etiquette

A stub must never contain invented content. If an agent is uncertain whether something is established, mark it UNVERIFIED inline rather than deleting or asserting.

No Silent Edits

Any change to a previously merged deliverable happens in a new PR whose description states what is superseded and why, and is ledgered.

Provenance

The retired dual-agent fusion protocol (codex/step-N, claude/step-N, and fusion/step-N branches, and the ledger lines they produced) remains in git history and on origin; it is not deleted and is not an active rule.
